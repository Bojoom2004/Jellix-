# Передача работы Claude — Jellix Core

## Кто я и моя роль

Я — второй разработчик проекта Jellix, работающий параллельно с Claude. Моя зона ответственности — переносимое ядро на C99, ограниченные по памяти структуры данных, инструменты и тесты, анализ интеграции с ActSDK и техническое ревью. Я не считаю аппаратные предположения фактами и не меняю HAL/регистры без подтверждения модели SoC и платы.

## Что сделано в этой итерации

Взята исходная кодовая база `Jellix_core_stage2.zip`; существующие модули сохранены. Добавлены:

- `core/jx_catalog.h/.c` — каталог игр без malloc: upsert по стабильному ID, поиск, флаги favorite/hidden, учёт запуска, сортировка по имени/недавнему запуску/платформе, поиск по названию и платформе, выдача видимых ID.
- `core/jx_log.h/.c` — кольцевой журнал фиксированного размера (32 записи по 72 байта), уровни debug/info/warn/error, timestamp, счётчик вытесненных записей, чтение от новых к старым.
- `core/jx_profile.h/.c` — фиксированный пул профилей платформ: upsert/find, выбор по имени платформы без учёта ASCII-регистра, активный профиль, безопасные значения по умолчанию, проверка remap/scale/rewind.
- `tests/test_core.c` расширен тестами каталога и журнала.
- `Makefile` обновлён, новые исходники входят в CORE.
- `ACTSDK_NOTES_RU.md` — выводы по загруженному SDK и ограничения.

Проверки: `make test` — 137/137 тестов успешно. `make mips`: компиляция каждого C-файла под `mipsel-unknown-elf`, `-march=mips32r2`, freestanding — проходит; если `llvm-size` отсутствует, используется `size`. Это НЕ является родной сборкой SDE/ActSDK и НЕ создаёт готовый `.app`.

## Важные выводы по ActSDK-master.zip

- SDK предназначен для Actions SoC под µC/OS.
- `case/makefile/makefile_app.rules` называет MIPS 4KEc, little-endian, `-mtune=24kec`, `-mips32r2`.
- Ожидаются внешние `sde-gcc`, `sde-ld`, `sde-objcopy`, `sde-objdump`, `sde-strip`; их бинарники в загруженном SDK не найдены.
- Есть app examples, `exe.xn`, `case.xn`, API headers/libraries, LCD driver sources и варианты LCD panel configs. Наличие панельных конфигураций не подтверждает конкретную матрицу J6/X20 mini.
- Владелец подтвердил ATS3603 физически по маркировке чипа в разобранной консоли. Для аппаратной интеграции всё ещё нужны маркировка/ревизия платы, LCD panel и дамп штатной прошивки. Не смешивать семейства ATJ2259B, ATJ227X и ATS3603.
- Репозиторий https://github.com/ovsky/RE-ATS3603 — важный источник по ATS3603 и родственным PowKiddy; использовать как исследовательский материал, сверяя с конкретной платой.

## Как продолжать

1. Не перезаписывать новые модули без согласования; интегрировать их в общую ветку.
2. Следующая задача — `jx_storage`/`jx_scanner` через абстрактные callbacks, не завязываясь на POSIX или конкретную SDK FS.
3. Добавить сериализацию профилей и каталога в текстовые файлы; файловый I/O оставить HAL callbacks.
4. Для настоящего устройства нужен подтверждённый SoC, плата/ревизия, LCD panel, stock firmware dump и родной SDE toolchain.

## Контракт кода

- C99, `-Wall -Wextra -Werror`.
- Не использовать malloc/calloc/realloc в переносимом ядре.
- Фиксированные размеры и caller-owned buffers.
- Все новые алгоритмы покрывать тестами ПК.
- Не обращаться к MMIO из portable core.
- Сохранять прежние публичные API, если нет отдельного согласования.
