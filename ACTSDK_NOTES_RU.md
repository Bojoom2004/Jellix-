# Заметки по ActSDK (анализ загруженного ActSDK-master.zip)

## Что подтверждено содержимым SDK

- SDK предназначен для Actions SoC под µC/OS; в `README.md` нет указания конкретной модели кристалла.
- Примерная конфигурация приложений в `case/makefile/makefile_app.rules` явно называет MIPS 4KEc, little-endian (`ENDIAN=EL`), `-mtune=24kec`, `-mips32r2`.
- Штатный SDK build ожидает внешние `sde-gcc`, `sde-ld`, `sde-objcopy`, `sde-objdump`, `sde-strip`. Эти исполняемые файлы не обнаружены в загруженном архиве; сам SDK содержит исходники, заголовки, библиотеки и Makefile-правила.
- Образ приложения называется `*.app`; Makefile использует `exe.xn`, `case.xn`, `VADDR`, карты линковки и набор системных библиотек из `psp_rel/lib` и `case/lib`.
- SDK содержит заголовки µC/OS/ядра и API, а также LCD driver source и несколько профилей панелей, включая 240x320 панели с контроллерами ILI9325/ILI9320. Наличие этих примеров не доказывает, что именно такая матрица стоит в целевой приставке.
- Примеры приложений используют API-библиотеки `applib_api.a`, `commonui_api.a`, `gui_api.a`, `syscall_api.a`, `kmodule_api.a` и др. Это пригодная отправная точка для HAL, но API нужно сверить с конкретной прошивкой/платой.

## Что пока нельзя заключать

- Архив SDK сам по себе не подтверждает, что целевое устройство имеет ATJ227X, ATJ2259B или ATS3603.
- Нельзя выбирать LCD-профиль по одному факту наличия исходников в SDK.
- Нельзя писать прямые MMIO-драйверы без подтверждённой модели SoC, ревизии платы, схемы/распиновки и соответствующей главы даташита.
- Компиляция переносимого ядра Clang target `mipsel-unknown-elf` — это проверка синтаксиса/ABI-совместимости, но не эквивалент сборки родным `sde-gcc` и не полноценная линковка `.app`.

## Следующий шаг по SDK

1. Получить/собрать совместимый SDE toolchain (`sde-gcc` и binutils) и зафиксировать версию.
2. Создать минимальное приложение на базе `case/apps/config` с `exe.xn`/`case.xn` из SDK.
3. Сверить экспортируемые функции `applib`, `GUI`, key, LCD, sound и filesystem API с библиотеками целевой штатной прошивки.
4. Только после подтверждения SoC и платы выбирать конкретные драйверы.
